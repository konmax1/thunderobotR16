# Thunderobot R16 (Hunter Blade 16) — Linux

Драйвер ядра `gwmi-wmi` и скрипт `power-mode.sh` для ноутбука Thunderobot
Radiant R16 (Hunter Blade 16) на платформе Bitland. Дают под Linux то, что в
Windows делает Thunderobot Control Center: переключение режима
производительности вместе с лимитом мощности GPU, управление вентиляторами и
статичную подсветку клавиатуры и логотипа на крышке.

| Что | Интерфейс | Чем пользоваться |
|---|---|---|
| Режим: максимум / баланс / экономия | `platform_profile` + power-profiles-daemon | `power-mode.sh power N`, трей KDE/GNOME |
| Лимит мощности GPU (TGP) | пересчитывается прошивкой через NVPCF | меняется вместе с режимом |
| Вентиляторы | hwmon `gwmi_wmi` (`pwm1`/`pwm2`) | CoolerControl или `power-mode.sh fan` |
| Подсветка: 3 зоны клавиатуры + крышка | LED-класс, 4 multicolor-устройства | `power-mode.sh light` |
| Датчики и обороты | hwmon `temp1`/`temp2`, `fan1`/`fan2` | `sensors`, CoolerControl, `power-mode.sh status` |

Подробности по драйверу, протоколу WMI, hwmon и подсветке —
в [`gwmi-wmi/README.md`](gwmi-wmi/README.md).


## Быстрый старт

Нужны заголовки текущего ядра, `dkms` и `sudo`.

```sh
sudo cp -r gwmi-wmi /usr/src/gwmi-wmi-1.4
sudo dkms add     -m gwmi-wmi -v 1.4
sudo dkms build   -m gwmi-wmi -v 1.4
sudo dkms install -m gwmi-wmi -v 1.4 --force
echo gwmi-wmi | sudo tee /etc/modules-load.d/gwmi-wmi.conf
sudo modprobe gwmi-wmi
```

После этого проверьте, что устройства появились:

```sh
./power-mode.sh status
./power-mode.sh fan
./power-mode.sh light
```

Дальше — на выбор:

- **Вентиляторы.** Настройте график в [CoolerControl](https://coolercontrol.org):
  устройство `gwmi_wmi`, каналы `fan1`/`fan2`, датчики `temp1` (CPU) и
  `temp2` (GPU). Это штатный способ, скрипт кривую не строит.
- **Подсветка.** Задайте цвета вручную или добавьте `power-mode.sh light ...`
  в автозапуск: после перезагрузки прошивка возвращает своё поведение.

## Команды `power-mode.sh`

Скрипт не требует установки и работает из любого каталога. Команды, меняющие
состояние, сами перезапускаются через `sudo`; `status`, `fan` и `light` без
аргументов работают от обычного пользователя.

### Режим питания

```sh
./power-mode.sh power 0    # максимум
./power-mode.sh power 1    # сбалансированный (заводской)
./power-mode.sh power 2    # энергосбережение
```

| Режим | `platform_profile` | TGP GPU |
|---|---|---|
| `0` | `performance` | ~115 Вт + Dynamic Boost (до 140 Вт) |
| `1` | `balanced` | ~95 Вт |
| `2` | `power-saver` / `low-power` | ~80 Вт |

Режим выставляется через `power-profiles-daemon`, если он запущен, иначе
записью в `/sys/firmware/acpi/platform_profile` (там третий профиль
называется `low-power`). После смены скрипт ждёт 5 секунд и показывает лимиты
GPU: `nvidia-smi` применяет новое значение с задержкой. `Current Power Limit`
— величина динамическая, в простое может подниматься до 140 Вт.

### Состояние

```sh
./power-mode.sh status
```

Показывает текущий профиль, лимиты пакета CPU из RAPL (PL1/PL2), текущий и
заводской лимит GPU, обороты и режим обоих вентиляторов, температуры CPU/GPU
(hotspot из EC).

### Вентиляторы

```sh
./power-mode.sh fan                 # состояние (без root)
./power-mode.sh fan auto            # оба — по кривой EC (по умолчанию)
./power-mode.sh fan full            # оба на полную скорость
./power-mode.sh fan 60              # оба вручную, 60 %
./power-mode.sh fan 1 40            # только вентилятор 1 (CPU), 40 %
./power-mode.sh fan 2 auto          # только вентилятор 2 вернуть в auto
```

- `0 %` — минимальные ~780 об/мин, вентилятор не останавливается; `100 %` —
  максимум ~4820 об/мин. Проценты линейно переводятся в `pwm` 0–255.
- Пока включён ручной режим, драйвер раз в секунду переписывает заданный
  уровень: EC сам возвращает свою кривую через 2–5 секунд.
- При 95 °C и выше по датчикам EC ручной уровень игнорируется и включается
  полная скорость.
- Ручной режим — это фиксированная скорость, а не кривая. Для повседневной
  работы используйте CoolerControl.

### Подсветка

```sh
./power-mode.sh light                    # состояние (без root)
./power-mode.sh light lid red            # логотип крышки — красный
./power-mode.sh light left 00ff00        # левая треть — зелёный (RRGGBB)
./power-mode.sh light right blue         # правая треть — синий
./power-mode.sh light kbd white          # вся клавиатура (left+middle+right)
./power-mode.sh light all off            # погасить всё
./power-mode.sh light lid bright 1       # яркость: 0 — выкл, 1 — низкая, 2 — макс.
./power-mode.sh light kbd mode fade      # анимация (проверены static и off)
```

- Зоны: `left`, `middle`, `right`, `lid`, `kbd` (три зоны клавиатуры), `all`.
- Цвета: `RRGGBB` или `red`, `green`, `blue`, `white`, `yellow`, `orange`,
  `cyan`, `magenta` (`purple`), `violet`, `off`.
- Яркость у трёх зон клавиатуры общая — так устроена прошивка; у крышки своя.
- Режимы: `off static blink fade heartbeat wave random rainbow`. Цвет
  гарантированно работает в `static`; в анимациях прошивка может его
  игнорировать.
- Состояние подсветки прошивка не умеет читать, поэтому драйвер помнит
  последние записанные значения и повторяет их после выхода из сна. После
  перезагрузки цвета нужно задать заново.

## Как это работает

- Фирменная утилита общается с ACPI-устройством `\_SB.GWMI` через legacy
  WMI-блок `644C5791-B7B0-4123-A90B-E93876E0DAAD`: 32-байтный буфер,
  `0xFA00` — чтение, `0xFB00` — запись, затем отдельный `WQAA` за ответом.
- Режим питания — EC-регистр `APMD` (`0x95`), значения 0/1/2. Прошивка сама
  пересчитывает лимиты NVPCF, которые забирает драйвер NVIDIA.
- Вентиляторы — «пользовательские» уровни UFA1/UFA2 (`0x2C`/`0x2D`); драйвер
  отдаёт их как стандартный hwmon, поэтому работает CoolerControl.
- Подсветка — WMI-функция `0x0100`: зона, режим, яркость и цвет в одном
  аргументе; драйвер превращает её в четыре LED-устройства.

Полная карта функций WMI/EC, включая нереализованные (Win-клавиша, тачпад,
WMI-события, battery care, MUX), — в разделе
[«Доступные функции WMI/EC»](gwmi-wmi/README.md#доступные-функции-wmiec-не-реализованы).

## Требования

- Ядро Linux с заголовками (`linux-headers-$(uname -r)`), `dkms`, `make`, `gcc`.
- `sudo` для установки модуля и записи в sysfs.
- Опционально: `power-profiles-daemon` (без него скрипт пишет в sysfs напрямую),
  драйвер NVIDIA (для строк с лимитами GPU в `status`), CoolerControl
  (для кривой вентиляторов).

Проверено на Thunderobot Radiant R16 (Hunter Blade 16), Ubuntu-подобном
дистрибутиве, ядре `7.3.0-9-generic`, KDE/Wayland и дискретной NVIDIA.
Драйвер собирается через DKMS и пересобирается при обновлении ядра.

## Ограничения

- Поддержка написана под эту модель и эту прошивку. Нумерация зон подсветки,
  коды режимов и границы вентиляторов у других Bitland/Casper могут отличаться.
- Температуры `temp1`/`temp2` — hotspot-значения из EC, они на 10–20 °C выше
  показаний `nvidia-smi`/`sensors`.
- Режим питания после сна восстанавливает EC/прошивка, а не драйвер.
- Драйвер не обрабатывает WMI-события: Fn-клавиша смены режима в Linux ничего
  не делает.
- Верхняя граница ~4820 об/мин и уровни EC `0x10`/`0x64` определены
  эмпирически.
- `nvidia-smi` показывает новый лимит GPU с задержкой 10–30 секунд.

## Диагностика

Каталог `diagnostics/` — история исследования протокола, а не рабочие
утилиты:

- `probe-bitland-wmi.sh` — пытается привязать альтернативный драйвер
  `bitland-mifs-wmi` к нескольким GUID.
- `test-bitland-guid.sh` — собирает локальный `bitland-mifs-wmi.ko` и
  проверяет каждый GUID через `force_guid`.
- `bitland-probe/` — исходники и собранный `.ko` этого драйвера.
- `gwmi-power/` — минимальный тестовый драйвер, меняющий режим через APMD.

Эти пробы конфликтуют с `gwmi-wmi` за те же WMI-устройства. Перед запуском
выгрузите рабочий драйвер (`sudo modprobe -r gwmi_wmi`), после — загрузите
обратно (`sudo modprobe gwmi_wmi`). Для повседневного использования они не
нужны.
