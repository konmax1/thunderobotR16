# gwmi-wmi — режимы производительности, вентиляторы и подсветка Thunderobot R16 (Bitland)

Драйвер для ACPI-WMI интерфейса `GWMI`, который использует фирменная утилита
Thunderobot Control Center. Даёт Linux-эквивалент переключателя
«Офис / Игра / Максимум», управляет лимитом мощности GPU, позволяет
задавать скорость вентиляторов и цвет подсветки клавиатуры и логотипа на
крышке.

## Что делает

Регистрирует `platform_profile` с тремя профилями, hwmon с датчиками и
управлением вентиляторами и четыре LED-устройства для подсветки.

| Профиль | Режим EC (`APMD`, 0x95) | TGP GPU |
|---|---|---|
| `low-power` | 2 | ~80 Вт |
| `balanced` | 1 | ~95 Вт |
| `performance` | 0 | ~115 Вт + Dynamic Boost |

`Current Power Limit` в `nvidia-smi` — динамическая величина: под нагрузкой
она примерно равна TGP, в простое может подниматься до 140 Вт (потолок VBIOS).
Значения «просаживаются» на 10–30 секунд после переключения — это нормально.

## Управление: `power-mode.sh`

Переключать профиль можно из трея KDE/GNOME (power-profiles-daemon) или скриптом.
Команды, меняющие состояние, сами запрашивают root через `sudo`.

```
./power-mode.sh power 0    # максимум
./power-mode.sh power 1    # баланс
./power-mode.sh power 2    # экономия
./power-mode.sh status     # профиль, лимиты GPU, вентиляторы, температуры

./power-mode.sh fan                 # состояние вентиляторов (без root)
./power-mode.sh fan auto            # оба — по кривой EC (по умолчанию)
./power-mode.sh fan full            # оба на максимум
./power-mode.sh fan 60              # оба вручную, 60 %
./power-mode.sh fan 1 40            # только вентилятор 1 (CPU), 40 %
./power-mode.sh fan 2 auto          # только вентилятор 2 вернуть в auto

./power-mode.sh light                    # состояние подсветки (без root)
./power-mode.sh light lid red            # логотип крышки — красный
./power-mode.sh light left 00ff00        # левая треть — зелёный (RRGGBB)
./power-mode.sh light right blue         # правая треть — синий
./power-mode.sh light kbd white          # вся клавиатура (left+middle+right)
./power-mode.sh light all off            # погасить всё
./power-mode.sh light lid bright 1       # яркость 0 — выкл, 1 — низкая, 2 — макс.
./power-mode.sh light kbd mode fade      # анимация (проверены static и off)
```

Зоны: `left`, `middle`, `right`, `lid`, `kbd` (три зоны клавиатуры), `all`.
Цвета: `RRGGBB` или `red`, `green`, `blue`, `white`, `yellow`, `orange`,
`cyan`, `magenta`, `violet`. Яркость трёх зон клавиатуры общая, у логотипа
крышки — своя.

Проценты 0–100 пересчитываются в `pwm` 0–255. В ручном режиме 0 % — самая
низкая скорость (~780 об/мин), вентилятор не останавливается; 100 % — максимум
(~4820 об/мин).

## hwmon

`/sys/class/hwmon/hwmonN`, name `gwmi_wmi`:

```
temp1_input   CPU (hotspot), м°C
temp2_input   GPU (hotspot), м°C
fan1_input    вентилятор 1, об/мин
fan2_input    вентилятор 2, об/мин
pwm1, pwm2             уровень 0–255 (запись включает ручной режим)
pwm1_enable, pwm2_enable   0 — полная скорость, 1 — ручной, 2 — авто (кривая EC)
```

Особенности `pwm`:

- Диапазон 0–255 линейно отображается на уровни EC `0x10…0x64`
  (~780–4820 об/мин), поэтому весь диапазон полезен, а `pwm=0` не
  останавливает вентилятор.
- Чтение `pwm*` в авто-режиме возвращает оценку по оборотам
  (`rpm × 255 / 4820`), а не «всегда 255».
- Состояние защищено мьютексом; при ошибке записи в EC кэш откатывается.
- Прошивка EC раз в 2–5 секунд возвращает свои уровни в UFA1/UFA2, поэтому,
  пока включён ручной режим, драйвер переписывает заданный уровень каждую
  секунду. Без этого внешнее управление (CoolerControl) не работало бы.
- При 95 °C и выше по датчикам EC ручной уровень игнорируется и включается
  полная скорость.
- Вручную заданные уровни восстанавливаются после сна. Если драйвер
  загружается, а в EC остался ручной уровень (например, после сбоя), он
  сбрасывается в авто. При выгрузке модуля вентиляторы тоже возвращаются в авто.

Прямые команды без скрипта:

```
echo 1   | sudo tee /sys/class/hwmon/hwmonN/pwm1_enable
echo 128 | sudo tee /sys/class/hwmon/hwmonN/pwm1
echo 2   | sudo tee /sys/class/hwmon/hwmonN/pwm1_enable   # вернуть авто
```

## CoolerControl

Управлять вентиляторами удобнее всего в [CoolerControl](https://coolercontrol.org):
драйвер отдаёт стандартный hwmon-интерфейс, и приложение видит устройство
`gwmi_wmi` с каналами `fan1`/`fan2` и датчиками `temp1` (CPU) и `temp2` (GPU).

1. Cooling → `fan1` / `fan2` → назначить профиль (график, фиксированная
   скорость) и включить его.
2. Источник температуры — `temp1` (CPU) или `temp2` (GPU) устройства
   `gwmi_wmi`.
3. Профиль применяется к каналу: `pwm*` и `pwm*_enable` драйвера —
   стандартные атрибуты hwmon.

Настройки CoolerControl хранит в `/etc/coolercontrol/config.toml` и применяет
их при старте демона и после выхода из сна — в журнале это видно как
`Successfully applied:: gwmi_wmi | fan1 | ...`. Проверить, что демон видит
устройство:

```
journalctl -u coolercontrold | grep gwmi_wmi
```

## Подсветка

Драйвер создаёт четыре LED-устройства (multicolor) — по одному на зону:

| Устройство | Зона |
|---|---|
| `/sys/class/leds/gwmi_wmi::kbd_backlight-left` | левая треть клавиатуры |
| `/sys/class/leds/gwmi_wmi::kbd_backlight-middle` | средняя треть клавиатуры |
| `/sys/class/leds/gwmi_wmi::kbd_backlight-right` | правая треть клавиатуры |
| `/sys/class/leds/gwmi_wmi::lid` | логотип на крышке |

Статичный цвет задаётся стандартным атрибутом `multi_intensity` (R G B,
0–255) или коротким `rgb` (шестизначный hex):

```
echo 255 0 0 | sudo tee /sys/class/leds/gwmi_wmi::kbd_backlight-left/multi_intensity
echo 0000ff  | sudo tee /sys/class/leds/gwmi_wmi::kbd_backlight-right/rgb
echo ff8000  | sudo tee /sys/class/leds/gwmi_wmi::lid/rgb
```

Яркость — `brightness` (0 — выкл, 1 — низкая, 2 — высокая). У трёх зон
клавиатуры она общая: так устроена прошивка, драйвер сам переписывает все
три зоны при изменении. У крышки яркость своя.

```
echo 1 | sudo tee /sys/class/leds/gwmi_wmi::kbd_backlight-left/brightness
```

Режим — `mode`, по умолчанию `static`. Доступные значения:
`off static blink fade heartbeat wave random rainbow`
(список также в `available_modes`). Проверены `static` и `off`; в
анимированных режимах прошивка, скорее всего, игнорирует заданный цвет.

```
cat  /sys/class/leds/gwmi_wmi::lid/available_modes
echo fade | sudo tee /sys/class/leds/gwmi_wmi::lid/mode
```

Прошивка не умеет читать состояние подсветки, поэтому драйвер помнит
последние записанные значения и повторяет их после выхода из сна. После
перезагрузки подсветка возвращается к заводскому поведению — цвета нужно
задать заново (например, скриптом при входе в систему).

Для экспериментов у WMI-устройства есть отладочный атрибут `light_raw`
(формат: `зона режим яркость rrggbb`, всё в hex):

```
echo "8 1 2 ff0000" | sudo tee /sys/bus/wmi/devices/644C5791-B7B0-4123-A90B-E93876E0DAAD/light_raw
```

## Протокол

Legacy WMI data block `644C5791-B7B0-4123-A90B-E93876E0DAAD`
(ACPI-устройство `\_SB.GWMI`, методы `WSAA`/`WQAA`), буфер 32 байта LE:

```
[0..1]   команда: 0xFA00 — чтение, 0xFB00 — запись
[2..3]   функция: 0x0100 — подсветка, 0x0200 — датчики,
                  0x0205 — уровни вентиляторов, 0x0300 — режим питания
                  (полная карта — в разделе «Доступные функции WMI/EC»)
[4..7]   аргумент 0
[8..11]  аргумент 1
[12..15] аргумент 2
```

Ответ забирается отдельным вызовом `WQAA` после каждой команды.

- Режим питания хранится в EC-регистре `0x95`, значение 0/1/2. Прошивка сама
  пересчитывает лимиты NVPCF (`\_SB.NPCF`) и сообщает их драйверу NVIDIA.
- Функция `0x0200` возвращает датчики: CPU °C, GPU °C, обороты вентиляторов 1 и 2.
- Функция `0x0205` пишет «пользовательские» уровни вентиляторов UFA1/UFA2/UFA3
  (аргументы 0/1/2, регистры EC `0x2C`/`0x2D`/`0x3E`). UFA3 драйвер всегда
  держит в auto. Чтения у функции нет, поэтому текущие уровни читаются прямо из
  EC через `ec_read()`.
- Функция `0x0100` управляет подсветкой: аргумент 0 — зона (`0x03`/`0x04`/`0x05`
  — правая/средняя/левая зона клавиатуры, `0x06` — все зоны клавиатуры,
  `0x08` — логотип на крышке), аргумент 1 — упакованный цвет: биты 31:28 —
  режим (1 — статичный), 27:24 — яркость (0–2), 23:16 — R, 15:8 — G, 7:0 — B.

Уровень вентилятора в EC — это не процент заполнения:

```
0x00         остановлен
0x10 – 0x64  примерно линейно, ~780 – ~4820 об/мин
0x65 – 0xFE  EC обрезает до 0x64 (максимум)
0xFF         авто (кривая EC), состояние по умолчанию
```

## Доступные функции WMI/EC (не реализованы)

Прошивка умеет больше, чем использует драйвер 1.4. Ниже — карта на будущее:
ничего из этого не реализовано и, кроме отмеченного, на этой машине не
проверялось. Формат команд — тот же 32-байтный буфер, что в разделе
«Протокол»: `[0..1]` — `0xFA00`/`0xFB00`, `[2..3]` — функция, `[4..7]`,
`[8..11]`, `[12..15]` — аргументы 0/1/2. Функция `0x0200 SET` дополнительно
читает байт `[20]`.

### Карта GWMI `644C5791-…`

| Команда | Функция | Аргументы | Назначение | Статус |
|---|---|---|---|---|
| GET | `0x0200` | — | CPU/GPU °C, обороты fan1/fan2, режим подсветки; побочно ставит `OMCC=1` | используется |
| GET | `0x0201` | — | тип клавиатуры: `0x34` RGB, `0x35` белая | не нужно |
| GET | `0x0202` | — | `ENTP` (тачпад), `AWMI`, флаг платы, число вентиляторов `CMSR(0xD8)+1` | не нужно |
| GET | `0x0203` | — | состояние MUX (`SAPD` → 1/2/3) | не реализовано |
| GET | `0x0204` | — | `HSRE` (1/2) | неизвестно |
| GET | `0x0205` | — | константа 4 | не нужно |
| GET | `0x0206` | — | `OMCC`, `W140` | неизвестно |
| GET | `0x0207` | — | `VGAT`, `RPM5` (16 бит) | не нужно |
| GET | `0x0300` | — | `APMD` (0/1/2) | используется |
| GET | `0x0400` | — | константы 1/1 | не нужно |
| SET | `0x0100` | зона, цвет | подсветка | используется |
| SET | `0x0200` | arg0=0, байт 20=0/1 | блокировка Win-клавиши (`DWNK`) | не реализовано |
| SET | `0x0202` | arg0=0/1 | тачпад выкл/вкл (`TPOF`/`TPON`) | не реализовано |
| SET | `0x0203` | arg0=1/2/3 | MUX: hybrid / dGPU / iGPU | не реализовано, рискованно |
| SET | `0x0204` | arg0=1/2 | `HSRE=0/1` | неизвестно |
| SET | `0x0205` | arg0/1/2 | уровни UFA1/UFA2/UFA3 | используется |
| SET | `0x0206` | arg0, arg1 | запись `OMCC` (дважды в один бит) | не трогать |
| SET | `0x0300` | arg0=0/1/2 | `APMD` + лимиты NVPCF | используется |
| SET | `0x0400` | arg0/1/2=1 | очистка `PEMR`/`CCHR`/`CAMR` | только для событий |

### Win-клавиша (`0x0200 SET`)

`arg0=0`, байт 20 = 0/1 → EC `DWNK` (`0x50`, бит 0). Чтения через WMI нет;
текущее состояние можно прочитать из EC `0x50` через `ec_read()`. В текущем
драйвере нет записи байта 20 — для реализации понадобится raw-хелпер.
Риск низкий.

### Тачпад (`0x0202 SET`)

`arg0=0` → `TPOF=1` (выкл), `arg0=1` → `TPON=1` (вкл). Состояние читается
через GET `0x0202` (`DAT2 = ENTP`, EC `0x5F` бит 4). Риск низкий.

### WMI-события (`74286D6E-…`)

Драйвер не обрабатывает события. `_WED` возвращает 9 байт:

| Смещение | Поле | Смысл |
|---|---|---|
| 0 | `KBBL` | режим подсветки: 0/1/2 |
| 1 | `OFST` | тип: 5 — адаптер, 7 — performance, 8 — Control Center |
| 2 | `BNUD` | не изучено |
| 3 | `FNMX` | не изучено |
| 4 | `HDMI` | не изучено |
| 5 | `APID` | код адаптера/ошибки |
| 6 | `CAMR` | не изучено |
| 7 | `PEMR` | запрос смены режима |
| 8 | `CCHR` | запрос Control Center |

EC queries: `_QB5`/`_QB6` — подсветка, `_QB7` — performance (`OFST=7`,
`PEMR=1`), `_QB8` — Control Center (`OFST=8`, `CCHR=1`), `_Q9F` — адаптер
(`OFST=5`, `APID=0x9F`). Без обработчика Fn-клавиша режима на Linux ничего
не делает; клавиши подсветки меняют EC, но кэш драйвера не обновляется.
Для реализации: notify-handler + workqueue, `platform_profile_cycle()`,
очистка через SET `0x0400`.

### Battery care (`EC 0x69` + `0x96`)

| EC | Поле | Предположительно |
|---|---|---|
| `0x69` бит 4 | `BCTC` (`BCTF`) | флаг порога заряда |
| `0x69` бит 5 | `BMNC` (`BMNF`) | режим обслуживания |
| `0x69` бит 6 | `BDSO` (`BTVD`) | разряд/порог |
| `0x69` бит 7 | `BF10` | полный заряд 100% |
| `0x96` | `BCPS` (`XBCH`) | уровень заряда |

В ACPI эти поля не используются, стандартного
`charge_control_end_threshold` у `BAT0` нет. Названия совпадают с картой
похожего EC (HP Omen/IT8987E) с точностью до буквы, но семантика на этой
прошивке не подтверждена. Запись в EC рискованна: EC обслуживает ещё
батарею, lid и клавиатуру. Сначала — только чтение `0x69`/`0x96` при
разном заряде.

### MUX (`0x0203`)

MUX — Parade PS8461E (описан в SSDT14). SET `0x0203`: `arg0=1` →
`CMSW(0xD5,4)`, `arg0=2` → `CMSW(0xD5,1)`, `arg0=3` → `CMSW(0xD5,0)`;
затем `CMSW(0xD6,0xAA)`. По коду DSDT: 1 — hybrid, 2 — dGPU-only,
3 — iGPU-only (`GFXT=0`). GET `0x0203` возвращает `SAPD` → 1/2/3.
Риск высокий: чёрный экран, переинициализация GPU, настройка
Wayland/Xorg. Нужен план восстановления.

### OMCC / XFCD (`0x0206`, EC `0x62`/`0x63`)

EC `0x62` бит 0 — `OMCC`, ручное управление вентиляторами. GET `0x0200`
ставит `OMCC=1` при каждом чтении датчиков; SET `0x0206` пишет один и тот
же бит дважды (`arg0`, `arg1`), поэтому семантика неочевидна. EC `0x63`
(`XFCD`) — таймер возврата к авторежиму; в нашем DSDT не описан. Текущий
1-секундный hold работает, менять не нужно. Пока ручной режим включён,
горячая клавиша max fan может перебиваться hold'ом.

### HSRE (`0x0204`)

SET `arg0=1` → `HSRE=0`, `arg0=2` → `HSRE=1` (только для board ID
`0x0A19E509`/`0x0A45E509`). GET возвращает 1/2. Назначение неизвестно;
не трогать.

### Датчики (`0x0207`, EC `GFA`/`RPM`)

GET `0x0207` — `VGAT` + `RPM5` (16 бит); возможно, третий вентилятор или
помпа. GET `0x0202` говорит, что вентиляторов два, поэтому ценность
низкая. EC `0x2E`/`0x2F`/`0x3D` — `GFA1/2/3` (фактический уровень),
`0xB0–0xB4` — `RPM1–5` (тахометры). Драйвер уже получает обороты через
`0x0200`.

### NVPCF (`NVDA0820`)

В SSDT14 есть `NPCF` (`_HID = NVDA0820`) с `_DSM` UUID
`36b49710-2483-11e7-9598-0800200c9a66`; он выставляет GPU-лимиты
`ACBT/ATPP/AMAT/AMIT` в зависимости от `APMD` и `GPUM`. Прямое управление
не рекомендую: это зона NVIDIA Dynamic Boost, драйвер NVIDIA может
использовать её сам.

### Что не представляет ценности

- GET `0x0201` — тип клавиатуры.
- GET `0x0205` — константа 4.
- GET `0x0207` — `RPM5`, если третьего вентилятора нет.
- SET `0x0400` отдельно — только очистка флагов событий.
- `101F83BB` (WMIA) — только `OSDV`, остальное пусто.
- `2BC49DEF` (WMDE) и `1F13AB7F` (WMTE) — тестовые заглушки.
- `ABBC0F20/40…48` — пустые WMI-блоки.

Всё перечисленное — только карта. Ничего из этого в драйвере 1.4 не
реализовано; перед реализацией каждую функцию нужно проверять на этой
машине.

## Установка

```
sudo dkms add -m gwmi-wmi -v 1.4
sudo dkms build -m gwmi-wmi -v 1.4
sudo dkms install -m gwmi-wmi -v 1.4 --force
sudo depmod -a
echo gwmi-wmi | sudo tee /etc/modules-load.d/gwmi-wmi.conf
```

Исходники должны лежать в `/usr/src/gwmi-wmi-1.4` вместе с `dkms.conf` и
`Makefile`. Модуль собирается автоматически при обновлении ядра (DKMS).
После изменения исходников пересоберите модуль той же последовательностью
(`dkms remove -m gwmi-wmi -v 1.4 --all`, затем `add`/`build`/`install`) и
перезагрузите: `sudo modprobe -r gwmi_wmi && sudo modprobe gwmi_wmi`.

### Обновление с более ранних версий

```
sudo dkms remove -m gwmi-wmi -v <старая> --all
sudo rm -rf /usr/src/gwmi-wmi-<старая>
sudo cp -r gwmi-wmi-1.4 /usr/src/    # gwmi-wmi.c, Makefile, dkms.conf
```

Затем выполните команды `dkms add/build/install` из раздела «Установка».

## Удаление

```
sudo rm /etc/modules-load.d/gwmi-wmi.conf
sudo dkms remove -m gwmi-wmi -v 1.4 --all
sudo rm -rf /usr/src/gwmi-wmi-1.4
sudo modprobe -r gwmi_wmi
echo balanced | sudo tee /sys/firmware/acpi/platform_profile
```

## Ограничения

- Проверено только на Thunderobot Radiant R16 (Hunter Blade 16),
  BIOS с ACPI-устройством `GWMI`.
- Датчики температуры — это hotspot-значения из EC, они выше показаний
  `nvidia-smi`/`sensors` на 10–20 °C.
- Верхняя граница 4820 об/мин и уровни EC `0x10`/`0x64` определены
  эмпирически; на другой ревизии прошивки могут отличаться.
- Драйвер не обрабатывает WMI-события (`74286D6E-...`); что в них есть —
  в разделе «Доступные функции WMI/EC».
- Нумерация зон подсветки и коды режимов определены на этом ноутбуке. У других
  моделей Bitland/Casper они отличаются (например, логотип там — зона `0x07`);
  для проверки используйте `light_raw`.
- Анимированные режимы (`blink`, `fade`, …) прошивка может понимать по-своему;
  назначение режимов проверено только для `static` и `off`.
- Режим питания после сна драйвер не восстанавливает — это делает EC/прошивка.
